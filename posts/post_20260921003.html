避坑指南：物联网项目最容易踩的 7 个工程陷阱

基于码视野团队 6 年、30+ IoT 项目的实战经验，我们整理了甲方和开发团队最常踩的 7 个工程陷阱。

陷阱 1：低估协议兼容成本

症状：项目启动时以为设备都支持 MQTT，进场后发现 70% 是 Modbus RTU 老设备，需要网关转换。

解决方案：合同签订前要求甲方提供设备通信协议清单，明确列出每类设备的通信接口（RS485/Ethernet/4G）、协议类型、波特率参数等。

陷阱 2：MQTT Broker 部署在公网无 TLS

症状：为了省事直接暴露 1883 端口，设备数据被爬虫采集，更严重的是有人通过伪造设备 ID 下发错误控制指令。

解决方案：生产环境强制启用 TLS（端口 8883），配置 X.509 双向证书认证，EMQX 开启 ACL 权限控制。

陷阱 3：用关系型数据库存时序数据

症状：用 MySQL 存储每秒上报的传感器数据，3 个月后单表破亿，查询超时，数据库服务器 CPU 爆满。

解决方案：时序数据必须用时序数据库：InfluxDB（轻量级，适合中小规模）或 TimescaleDB（PostgreSQL 扩展，适合需要复杂 SQL 分析的场景）。

陷阱 4：没有消息幂等处理

症状：QoS=1 模式下，网络抖动会导致同一条消息被重复投递，导致数据库写入重复数据，累计偏差越来越大。

解决方案：每条消息携带唯一的 msg_id（时间戳 + 设备ID + 序列号），消费端做幂等校验，重复消息直接丢弃。

陷阱 5：边缘计算节点时钟不同步

症状：5 台工业网关的系统时钟相差 3-15 分钟，导致时序数据排序混乱，告警时间线错乱。

解决方案：所有网关节点配置 NTP 服务，同步到同一个时间服务器，时间戳统一使用 UTC。
